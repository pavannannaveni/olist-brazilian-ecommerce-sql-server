# Data Dictionary

This dictionary describes the tables in the Olist Brazilian E-Commerce dataset loaded into the `Ecommerce` SQL Server database. The companion file `data_dictionary_columns.csv` lists the column names and SQL types found in this database.

## Table grains and logical relationships

| Table | One row represents |
|---|---|
| `orders` | One order |
| `order_items` | One item within an order |
| `order_payments` | One payment record or sequence for an order |
| `order_reviews` | One review record |
| `customers` | One customer record associated with an order |
| `products` | One product |
| `sellers` | One seller |
| `category_translation` | One product category translation |
| `geolocation` | One geolocation record; a ZIP prefix may have multiple records |

Common logical joins:

- `orders.customer_id` → `customers.customer_id`
- `order_items.order_id` → `orders.order_id`
- `order_items.product_id` → `products.product_id`
- `order_items.seller_id` → `sellers.seller_id`
- `order_payments.order_id` → `orders.order_id`
- `order_reviews.order_id` → `orders.order_id`
- `products.product_category_name` → `category_translation.product_category_name`

Customer, seller, and geolocation tables can have multiple records for a ZIP prefix. Check the data grain before joining them. Also, aggregate `order_items` and `order_payments` separately by `order_id` before joining them; otherwise, multiple items and payments can multiply totals.

## `orders`

| Column | Meaning |
|---|---|
| `order_id` | Unique identifier for an order |
| `customer_id` | Identifier for the customer record associated with the order |
| `order_status` | Current recorded status of the order |
| `order_purchase_timestamp` | Date and time the order was placed |
| `order_approved_at` | Date and time the order was approved |
| `order_delivered_carrier_date` | Date and time the order was handed to the carrier |
| `order_delivered_customer_date` | Date and time the order was delivered to the customer |
| `order_estimated_delivery_date` | Estimated delivery date |

## `order_items`

| Column | Meaning |
|---|---|
| `order_id` | Identifier for the order containing the item |
| `order_item_id` | Sequential item number within the order |
| `product_id` | Identifier for the product |
| `seller_id` | Identifier for the seller |
| `shipping_limit_date` | Latest date by which the seller should hand the item to the carrier |
| `price` | Item price, in Brazilian reais (BRL) |
| `freight_value` | Freight charge for the item, in BRL |

## `order_payments`

| Column | Meaning |
|---|---|
| `order_id` | Identifier for the order |
| `payment_sequential` | Sequence number for a payment record within the order |
| `payment_type` | Payment method |
| `payment_installments` | Number of installments |
| `payment_value` | Value of the payment record, in BRL |

## `order_reviews`

| Column | Meaning |
|---|---|
| `review_id` | Identifier for the review |
| `order_id` | Identifier for the reviewed order |
| `review_score` | Customer's review score, usually on a 1–5 scale |
| `review_comment_title` | Review title |
| `review_comment_message` | Review text |
| `review_creation_date` | Date and time the review was created |
| `review_answer_timestamp` | Date and time the review was answered |

## `customers`

| Column | Meaning |
|---|---|
| `customer_id` | Identifier for the customer record associated with an order |
| `customer_unique_id` | Identifier used to recognize the same customer across orders |
| `customer_zip_code_prefix` | Customer's ZIP-code prefix |
| `customer_city` | Customer's city |
| `customer_state` | Customer's state abbreviation |

## `products`

| Column | Meaning |
|---|---|
| `product_id` | Identifier for the product |
| `product_category_name` | Product category name in the source language |
| `product_name_lenght` | Length of the product name field; the source column uses this spelling |
| `product_description_lenght` | Length of the product description field; the source column uses this spelling |
| `product_photos_qty` | Number of product photos |
| `product_weight_g` | Product weight in grams |
| `product_length_cm` | Product length in centimeters |
| `product_height_cm` | Product height in centimeters |
| `product_width_cm` | Product width in centimeters |

## `sellers`

| Column | Meaning |
|---|---|
| `seller_id` | Identifier for the seller |
| `seller_zip_code_prefix` | Seller's ZIP-code prefix |
| `seller_city` | Seller's city |
| `seller_state` | Seller's state abbreviation |

## `category_translation`

| Column | Meaning |
|---|---|
| `product_category_name` | Product category name in the source language |
| `product_category_name_english` | English translation of the product category |

## `geolocation`

| Column | Meaning |
|---|---|
| `geolocation_zip_code_prefix` | ZIP-code prefix associated with the location |
| `geolocation_lat` | Latitude |
| `geolocation_lng` | Longitude |
| `geolocation_city` | City associated with the location |
| `geolocation_state` | State abbreviation associated with the location |

## Data notes

- The imported core-table columns are stored as `varchar`; analysis queries convert dates and amounts when needed.
- SQL Server has no primary or foreign key constraints defined on the imported tables. The relationships above are logical relationships used for analysis.
- One delivered order in September 2016 has no matching payment record in the imported payment table. The analysis keeps this visible as missing instead of recording it as zero.
